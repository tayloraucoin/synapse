# Start here

**What this is.** Synapse's docs: the practice (PEM, adopted in place; the rules people and agents build by, the roles, the templates, the workflows) and Synapse's own product and engineering documents. What the practice replaced is archived in [`decisions/imported/`](decisions/imported/README.md).

**Come here when.** You are new, you are back after a while, or you cannot remember which folder holds the thing you need.

**Start with.**

- **As a person:** [`workflows/README.md`](workflows/README.md), *How work moves*: ten minutes, and the whole system fits in your head.
- **As an agent:** [`index.md`](index.md), the agents' map, loaded in every session. It decides what wins when two files disagree.

## By the question you arrive with

| You are asking | Go to |
| --- | --- |
| How do I do work here? | [`workflows/`](workflows/README.md) for the game; `runbooks/` for procedures you follow by hand |
| How does the app behave? | [`../specs/web/ux/`](../specs/web/ux/) for the promoted areas; [`ux/`](ux/README.md) for the rest until MIG-1 promotes them |
| What are the rules? | [`design/`](design/README.md) and the product's layer in `apps/web/docs/design/`; `engineering/` ([conventions](engineering/codebase-conventions.md), [stack](engineering/tech-stack.md)); `product/`, `measurement/`; every ruling behind them is in [`decisions/`](decisions/records/README.md) |
| How is Synapse's code built? | `architecture/`, [`ai-guides/`](ai-guides/README.md) and `developer-guides/`: Synapse's documents from before the practice, being folded into PEM's slots |
| What is Synapse for? | `product/`: the value proposition, the walkthrough notes, the phase-two list |
| Who do I ask? | [`roles/`](roles/README.md): the cast, one prompt per seat |
| What changed from PEM? | [`pem/`](pem/README.md): each Synapse adaptation, for a PEM sync |

Every file, one line each: [`architecture/directory-map.md`](architecture/directory-map.md), generated by `yarn directory-map`.
