2026-09-05 · SET-2 · **`/verify` and `/reset` moved out of the `(auth)` route group into a new `(auth-pending)` group** (the URLs are unchanged — route groups do not appear in a path) · The `(auth)` layout redirects anyone with a session to `/`, which is right for AU-01/02/04 and breaks the other two. AU-05 is only reachable WITH a session: `/auth/confirm` verifies the recovery link, signs the person in, and redirects to `/reset`, where `updateUser({ password })` needs that session — under the `(auth)` gate the reset form could never render, so AC7 was unreachable as the routes stood. Each screen's gate lives in its own layout, so no page checks a session and the "no second gate" rule holds.

2026-09-05 · SET-3 · The path grammar lives in `@syn/constants` (`buildAssetPath`, `parseAssetPath`, `toStorageKey`, `isSafeAssetFileName`), not inline in the service and the route · Four places need the same answer to "is this a path this pipeline produced, and whose is it" — the mint, the avatar service, the read route, and the URL helper. 2026-09-05 · SET-3 · The object policies are `AS RESTRICTIVE`, which the ticket's advisory note does not specify · A permissive "deny" is not a deny: permissive policies are OR'd, so it grants nothing and prevents nothing, and the first permissive grant a future ticket adds would override it silently. The stated intent — "the policies exist so that a future JWT path fails closed" — is only true of a restrictive policy, which is AND'd. Each is scoped `bucket_id <> '<name>'` so the per-bucket names the ticket asks for are accurate and a future bucket is unaffected.
2026-09-05 · SET-3 · The three bucket rows are now `ON CONFLICT (id) DO UPDATE` rather than INF-5's `DO NOTHING` · The ticket's own advisory note recommends it. AC1's "running twice changes nothing" still holds — the values written are the same ones.
