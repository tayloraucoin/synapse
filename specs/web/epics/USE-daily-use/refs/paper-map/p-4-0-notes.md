## Dev note · The model: blocks, to-dos, where @ x 2410, y 2520

Dev note · The model

Time and tasks are kept apart and joined by a slot. A block is a container of time; a to-do lives in one pool; slotting a to-do into a block for a date is the only link.

↓ joined by ↓

Why kinds aren't places

A kind says what the time is for: it sets colour, Review's grouping and Make room's order. Type is a fact about one to-do (a context, in Getting Things Done's terms: @home, @errands, @calls, and Digital for anything on a screen). It lives on the to-do only: a block never filters by it, so any to-do can go in any To-dos block. Type helps when picking from the pool.

The same pattern already in use

Work is a block; work items sit in the pool; tiers slot them into a day (D-USE-31). To-dos blocks do the same with a where filter instead of tiers.

Slot

to-do × block × date · order. Made by the pull rule or by hand; removed at the block's end if not done, so the to-do is back in the pool.

Event

a fixed time on a date. Not slotted: it pins inside whatever block its time falls in.

Block

kind · start · end · repeat rule (Google Calendar's: RFC 5545 RRULE) or one date · fill: set items or from To-dos

To-do

name · length · type (Home, Errand, Call, Digital, Other) · day or none · repeats · reminder · notes

[PROPOSED] List-detail from a second break, --breakpoint-split 1024 (a new token, set by the panes' minimum widths: rail 220 + week 320 + day 360 + gutter and margins 72 = 972, rounded up). Below 1024, including 768 to 1023, Set my days keeps the phone's push: the week first, then the day with "Week" as the way back.

## Dev note · Linear status fill @ x 4820, y 7560

Dev note · Linear status fill

A Linear status shows as Linear draws it: a ring in the workspace's colour for that status, with a pie inside that fills as the issue moves through its group. In progress is yellow and partly filled, not a clock (Taylor, round 2).

Logged in day/overview.md, Open.

How the fill is worked out

Read the workspace's statuses from Linear, grouped by type (Backlog, Unstarted, Started, Completed, Canceled). Inside the Started group, ordered by Linear's position: fill = position ÷ (statuses in the group + 1). Lighthouse has five started statuses, so In progress (1st) is 1/6, Ongoing 2/6, Paused 3/6, In review 4/6, Changes requested 5/6. Completed is a full disc with a check; Backlog a dotted ring; Unstarted an empty ring; Canceled a grey disc with a cross.

To investigate

Whether Linear's API gives the position or only the order. When a workspace adds or removes a status, every fill in that group shifts; recompute on sync, never store the fraction. Colour is never alone: the status word always sits beside the shape.
